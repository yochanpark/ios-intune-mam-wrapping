# iOS 앱 Intune MAM Wrapping 기술 검증(PoC)

고객사 모바일 보안 PoC에서 "App Extension이 많은 iOS 앱을, Extension이 살아 있는 채로 Intune으로 감싸 MAM 정책으로 제어할 수 있는가"를 실기기로 검증한 작업이다.

> 회사 업무로 수행한 PoC라 명령어·설정값·계정 정보·산출물은 올리지 않고, **어떤 일을 했고 무엇을 밝혔는지만** 적었다.

| 개요 | |
|---|---|
| 역할 | 단독 수행(검증 설계 · 재서명 · 실기기 검증 · Entra/Intune 구성 · 결과 보고) |
| 결론 | **가능함을 실기기로 실증.** 단, 조건부 액세스의 "앱 보호 정책 필요" 조건은 구조적으로 통과할 수 없음을 규명 |
| 기술 | iOS 코드 서명 · Entitlements · Xcode · Intune App Wrapping Tool · Microsoft Entra ID · MSAL · Intune 앱 보호 정책 · 조건부 액세스 |

## 배경

실제 대상 앱은 개발사의 원본 파일 협조가 먼저 있어야 해서 바로 착수할 수 없었다.
그래서 **구조가 같은(App Extension 다수) 오픈소스 앱**을 대체 대상으로 골라, 같은 조건에서 가능 여부를 먼저 확인했다.

## 한 일

1. **대상 확보**: 소스 빌드를 먼저 시도했다. 한계를 확인한 뒤 공개 릴리스 파일로 경로를 바꾸고, Extension 6개 구조를 분석했다.
2. **Apple 개발자 자산 등록**: 메인 앱과 Extension별 App ID 7개, App Group, iCloud 컨테이너를 등록하고 프로필 7개를 발급했다.
3. **Extension을 살린 재서명**: 안쪽 프레임워크 → Extension → 앱 순서로 하나씩 수동 재서명했다(프레임워크 39개 포함). 일괄 서명 옵션으로는 내장 프레임워크가 다 서명되지 않는다는 것을 확인했다.
4. **실기기 크래시 원인 규명**: 설치 후 실행 즉시 종료되는 문제 2건을 크래시 리포트의 스택으로 추적해 iCloud, Siri 권한(Entitlement) 누락을 찾아냈다. 권한이 빠졌을 때 앱이 강제 종료되는 유형과 기능만 조용히 안 되는 유형을 구분해 정리했다.
5. **Entra ID 앱 등록**: 리디렉션 URI와 Intune 관리 API 권한을 구성하고 관리자 동의를 받았다.
6. **Wrapping 도구 문제 우회**: 최신 macOS에서 Wrapping 도구가 설정 파일 기록에 실패하는 문제를 찾아, MAM 설정을 수동으로 넣어 해결했다.
7. **앱 보호 정책 배포와 검증**: 정책을 만들어 배포하고, 실기기에서 MAM 로그인 화면과 화면 캡처 차단 등 데이터 유출 방지 동작을 확인했다.
8. **조건부 액세스 이슈 분석**: 직접 감싼 앱은 Microsoft 승인 앱 목록에 없어 "앱 보호 정책 필요" 조건을 통과할 수 없다는 구조적 제약을 밝혔다.

## 보고한 결론과 선행 조건

- Extension을 유지한 Wrapping은 기술적으로 가능하다.
- 실제 적용에는 다음이 먼저 필요하다.
  - 개발사가 제공하는 미암호화 원본 파일(스토어 배포본으로는 불가)
  - Apple 개발자·Entra ID·Intune 세 체계 각각의 관리 권한. 하나라도 없으면 중단된다.
  - 조건부 액세스 정책을 조정하거나 예외를 협의하는 일
  - 앱 버전업과 도구 업데이트 때마다 다시 작업하는 운영 프로세스
- 실제 대상 앱에 적용할 때의 항목별 예상 난이도(원본 확보, 권한 재현, 조건부 액세스, 지속 운영)를 정리해 전달했다.

## 정리한 것

- 착수 전 확인 사항, 대상 앱 분석 절차, 트러블슈팅 참고를 체크리스트로 만들어 실제 적용 단계에서 바로 쓰게 했다.
