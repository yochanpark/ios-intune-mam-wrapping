# 7. 조건부 액세스 정책 이슈

### 4.9 조건부 액세스 정책 이슈

로그인 과정에서 다음 순서로 차단되는 현상이 발생했습니다.

```
1차: MAM 로그인 화면 → 계정 로그인 성공
2차: "조직 데이터를 보호하려면 이 앱을 관리해야 합니다" → 재로그인 요구
3차: "로그인 실패 — 이 앱을 사용하도록 설정하지 않았습니다"
```

#### 원인 추적

Entra ID 조건부 액세스 정책을 확인한 결과, 대상 그룹에 적용 중인 정책을 발견했습니다.

```
정책명: {ADMIN}_mam_appprotection_policy
상태:   설정(활성화)
대상 리소스: 모든 리소스 (이전의 '모든 클라우드 앱')
액세스 제어 > 허용:
  ☑ 앱 보호 정책 필요
```

#### 기술적 분석

Microsoft 공식 문서(`concept-conditional-access-grant`)를 확인한 결과, **"Require app protection policy" grant control은 사전 승인된 특정 앱 목록에만 적용**되도록 설계되어 있습니다.

```
지원 앱 목록: Outlook, Teams, OneDrive, Edge, Adobe Acrobat Reader, ...
"앱이 목록에 없으면 앱 벤더에게 지원 여부를 확인하라"
```

추가로 이 조건은 **broker 앱(Microsoft Authenticator)을 통한 기기 등록**을 전제로 합니다.

즉 **Wrapping을 아무리 완전하게 수행해도, 커스텀 앱은 이 grant control을 통과할 수 없는 구조적 제약**이 존재합니다.

#### 검증 방법 및 해결 방향

| 방향 | 내용 |
|---|---|
| A. 예외 처리 | 조건부 액세스 정책의 "제외" 대상에 테스트 계정 추가 |
| B. 결론 도출 | 커스텀 LOB 앱은 해당 조건부 액세스와 양립 불가함을 기술 결론으로 정리 |

이 발견은 **실제 대상 앱 B 도입 시에도 동일한 제약이 발생할 수 있음을 시사**하므로, PoC의 유의미한 산출물입니다.
